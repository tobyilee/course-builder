# React 상태 관리 심화 — Managing State

> react.dev/learn/managing-state 7개 챕터를 ADDIE + Bloom's Taxonomy 기반으로 재구성한 9섹션·26클래스 온라인 강의. **v1.0.0**

---

## 한 줄 소개

useState는 익숙한데도 폼 상태에 boolean 4개를 만들었다가 모순 조합이 생기고, prop이 4단계를 통과만 하며 흐르고, 글 작성 탭만 바꾸면 이전 입력값이 새 글에 그대로 남는 — 그런 "state 통증"을 **진단하고 처방하는 사고법**을 익히는 코스입니다.

## 이 코스가 풀어주는 4가지 state 통증

대부분의 React 코드 스멜은 결국 다음 네 갈래로 환원됩니다.

| #   | 통증                | 증상                                                     | 처방하는 챕터       |
| --- | ------------------- | -------------------------------------------------------- | ------------------- |
| 1   | **중복 / 모순**     | 같은 정보를 여러 state에 복제해 paradox 조합이 만들어짐  | S1, S2              |
| 2   | **동기화 버그**     | props를 useState 초기값으로 mirror 했더니 갱신이 끊어짐  | S2                  |
| 3   | **Prop drilling**   | 깊은 트리를 통과하느라 무관한 컴포넌트가 prop만 흘려보냄 | S3 (1차) · S6 (2차) |
| 4   | **의도치 않은 리셋** | 트리 위치 규칙에 의해 state가 보존/리셋되며 버그가 생김  | S4                  |

여기에 **로직 응집(reducer, S5)** 과 **대규모 분산 상태 확장(reducer + context, S7)**, 그리고 **종합 안티패턴 진단(S8)** 이 더해져 하나의 사고 체계가 완성됩니다.

## 누구를 위한 코스인가

- TypeScript / JavaScript / React 함수형 컴포넌트 개발은 능숙한 **중급 개발자**
- useState 기본 사용, 이벤트 핸들링, props 흐름은 이미 알고 있음
- 그런데 **state 설계·구조화·공유·보존·리듀서·컨텍스트** 영역에서 한 단계 깊이를 올리고 싶은 사람

> 만약 useState 자체가 처음이라면 react.dev의 "State: A Component's Memory" 챕터를 먼저 읽고 오세요. 이 코스는 그 다음 단계입니다.

## 코스 구성

```
S0  오리엔테이션 — 왜 state 설계가 따로 필요한가             (2 classes)
S1  사고방식 전환 — 선언형 UI와 visual states로 반응하기      (3 classes)
S2  state 구조 설계 — 5가지 원칙으로 동기화 버그 차단         (4 classes)
S3  컴포넌트 간 state 공유 — Lifting State Up                (3 classes)
S4  state 보존과 리셋 — 트리 위치와 key prop                 (3 classes)
S5  Reducer로 state 로직 추출하기                            (4 classes)
S6  Context로 깊이 데이터 전달하기                           (3 classes)
S7  Reducer + Context로 확장하기                             (2 classes)
S8  종합 — 안티패턴 진단과 통합 케이스 스터디                (2 classes)
```

각 섹션은 **5\~9문항 형성평가 퀴즈**로 마무리합니다. 정답률뿐 아니라 오답에 왜 끌렸는지 해설(distractor rationale)이 함께 제공됩니다.

## 한눈에 보는 규모

- **9** 섹션 / **26** 클래스 / **207** 슬라이드
- **35** 학습목표 (Bloom 분포: Remember 2 · Understand 7 · Apply 10 · Analyze 7 · Evaluate 5 · Create 4)
- 강의 음성 약 **196분** (TTS 합성, 슬라이드별 자막 동기)

Bloom 분포가 단순 암기(Remember)보다 적용·분석·평가·창작 비중이 두드러지게 높습니다 — 정의를 외우는 코스가 아니라 **자기 코드의 통증을 진단·처방·재설계하도록** 설계되었습니다.

## 한 클래스가 어떻게 구성되는가

| 산출물            | 역할                                                                   |
| ----------------- | ---------------------------------------------------------------------- |
| **HTML slide**    | 4–7장의 핵심 시각 자료 (Marp 기반, 풋터에 LO id 표기)                   |
| **MD note**       | 400–900단어 학습 노트 — Intro / Concept / Example / Pitfalls / Recap   |
| **TTS transcript** | 슬라이드 큐(`[slide N]`)와 휴지 마커(`[pause:NNN]`)가 들어간 내레이션 |
| **per-slide MP3** | 슬라이드별 음성 + 전체 합본 `full.mp3`                                 |
| **section quiz**  | 5–9문항, 학습목표 매핑, distractor 해설 포함                           |

플레이어는 자막을 음성에 맞춰 한 줄씩 하이라이트하며 진행 상태를 저장합니다. 즐겨찾기 페이지 / 직전 위치 이어듣기 / 단축키 모두 지원합니다.

## 학습 흐름 권장

1. **S0 오리엔테이션**부터 순서대로 — 4가지 통증과 코스 맵이 이후 모든 챕터의 좌표가 됩니다.
2. 자기 프로젝트의 보고된 버그·코드 스멜 1개를 떠올리고 "이건 통증 #몇번인가?"를 짐작해 두세요. 각 챕터를 들으며 가설을 검증하는 방식이 가장 효과적입니다.
3. 섹션 끝 퀴즈는 **틀려도 괜찮습니다** — 오답 해설을 읽는 게 본 학습의 절반입니다.
4. S8 안티패턴 클리닉과 통합 케이스 스터디는 자신의 코드 리뷰 도구로 두고두고 재방문하세요.
