[slide 1]
이번 시간엔 자식 컴포넌트에 ref를 넘기는 방법을 봅니다.
[pause:400]
포워드레프에서 React 19의 ref-as-prop으로 진화한 흐름, 그리고 유즈임페러티브핸들까지 함께 다룹니다.

[slide 2]
상황을 그려볼게요.
[pause:400]
직접 만든 디자인 시스템에 MyInput이라는 컴포넌트가 있습니다.
[pause:400]
부모에서 거기에 ref를 꽂아서 focus를 부르고 싶어요.
[pause:500]
그런데 MyInput에 ref={inputRef}를 넘겨도, 그냥은 동작하지 않습니다.
[pause:500]
왜냐하면 ref는 prop이 아니거든요.
[pause:400]
컴포넌트 함수의 인자로 자동 전달되지 않습니다.
[pause:500]
해결 경로는 세 가지예요.
[pause:300]
React 18까지 쓰던 포워드레프, React 19의 ref-as-prop, 그리고 노출되는 API를 좁히는 유즈임페러티브핸들.
[pause:400]
하나씩 따라가 보죠.

[slide 3]
먼저 React 18까지의 방식, 포워드레프입니다.
[pause:500]
컴포넌트를 포워드레프로 감싸면, 함수 시그니처가 props 하나가 아니라 props와 ref 두 인자로 바뀝니다.
[pause:500]
이렇게 되는 거예요.
[pause:300]
포워드레프 안에 함수를 넣고, 그 함수가 props와 ref를 받아서 input에 ref={ref}로 그대로 꽂아주는 형태.
[pause:500]
부모는 평소처럼 inputRef를 만들어서 MyInput에 ref={inputRef}로 넘기면 됩니다.
[pause:500]
이 한 단계의 보일러플레이트가, 디자인 시스템 전반에 깔리던 시절이 꽤 길었어요.
[pause:300]
모든 노출 컴포넌트마다 포워드레프 래핑을 달고 살아야 했죠.

[slide 4]
이제 React 19의 변화입니다.
[pause:500]
ref가 그냥 prop처럼 동작합니다.
[pause:400]
function MyInput에서 props 디스트럭처링으로 ref를 바로 받아서, 안쪽 input에 그대로 꽂아주면 끝이에요.
[pause:500]
부모 쪽 사용법은 18 때와 똑같습니다.
[pause:300]
useRef로 inputRef를 만들고 MyInput에 ref={inputRef}를 넘긴다.
[pause:500]
포워드레프 래핑이 사라졌고, 디자인 시스템 보일러플레이트가 통째로 줄어들었습니다.
[pause:500]
마이그레이션은 codemod로 자동 전환이 가능해서, 점진 채택해도 괜찮아요.
[pause:400]
다만 라이브러리 호환성 때문에 한동안은 두 패턴이 공존합니다.
[pause:300]
어느 쪽 코드를 만나도 의도를 읽을 수 있어야 한다는 뜻이에요.

[slide 5]
이제 세 번째 도구, 유즈임페러티브핸들입니다.
[pause:500]
문제 상황을 먼저 짚을게요.
[pause:400]
ref를 그냥 노출해 버리면, 부모는 focus뿐 아니라 value, blur, select 같은 input의 모든 API에 접근할 수 있게 됩니다.
[pause:500]
캡슐화가 깨지는 거예요.
[pause:400]
자식이 의도한 명령형 표면이, 입력 DOM 전체로 줄줄 새어 나갑니다.
[pause:500]
그래서 유즈임페러티브핸들을 써요.
[pause:400]
ref와, focus 메서드 하나만 가진 객체를 반환하는 함수를 넘깁니다.
[pause:500]
내부에는 realInputRef를 따로 두고, 진짜 input DOM은 거기서 잡아두는 거죠.
[pause:400]
바깥에는 focus만 주는 facade를 노출합니다.
[pause:500]
이건 명령형 API를 의도적으로 좁히는 설계예요.
[pause:400]
노출이 좁을수록, 자식의 내부 구현을 바꿀 자유가 늘어납니다.
[pause:300]
나중에 input을 textarea로 바꾸더라도, 부모 코드는 깨지지 않아요.

[pause:400]

[pause:400]
아닙니다.
