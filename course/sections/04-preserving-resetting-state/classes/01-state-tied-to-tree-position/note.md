# state는 트리 위치에 묶인다 — 보존과 리셋의 기본 규칙

> LOs: LO-S4.1, LO-S4.2

## 개요

화면 위쪽에 점수 카운터가 있고, "Fancy 모드" 토글을 눌러 스타일이 화려한 버전과 평범한 버전을 바꿉니다. 토글을 몇 번이나 눌러도 카운터의 점수는 사라지지 않습니다 [slide 1]. props는 분명히 바뀌었는데 score state가 살아남는 이 현상이 오늘의 출발점입니다. "state는 컴포넌트 안에 산다"는 직관만으로는 설명되지 않는, 더 정확한 모델이 필요합니다.

## 핵심 개념

React는 우리가 만든 **컴포넌트 인스턴스 자체를 추적하지 않습니다**. 대신 렌더 트리에서 **그 컴포넌트가 차지하는 위치(slot)** 를 추적합니다 [slide 2]. JSX의 `<Counter />`는 "여기 Counter라는 컴포넌트가 있다"가 아니라 "이 위치에는 Counter 타입이 들어가야 한다"는 명세에 가깝습니다. 같은 변수에 담긴 element를 두 번 써도 트리에서 두 위치를 차지하면 **두 개의 독립된 state**가 만들어집니다.

```jsx
const counter = <Counter />;
return <div>{counter}{counter}</div>; // 두 슬롯 = 두 state
```

여기서 두 가지 규칙이 도출됩니다 [slide 3].

- **규칙 1 — 같은 위치 + 같은 컴포넌트 타입 = state 보존.** props가 바뀌어도, 부모가 다시 렌더되어도, React는 그 슬롯의 state를 그대로 붙여 둡니다.
- **규칙 2 — 같은 위치인데 컴포넌트 타입이 다르면 = state 파괴.** 이전 컴포넌트는 unmount되고 그 하위 트리의 모든 state가 함께 사라집니다.

이 두 줄을 외우면 보존/리셋의 90%를 예측할 수 있습니다. 나머지 10%는 다음 두 class에서 다룰 의도된 리셋과 함정입니다.

## 예시

먼저 보존되는 경우입니다 [slide 4].

```jsx
{isFancy ? <Counter isFancy={true} /> : <Counter isFancy={false} />}
```

삼항의 두 분기 모두 부모의 같은 위치에 `Counter`를 렌더합니다. 같은 위치 + 같은 타입이므로 score는 토글해도 살아남고, props만 갈아끼우는 효과가 납니다. 시각은 바뀌지만 정체성은 유지됩니다.

다음은 리셋되는 경우입니다 [slide 5].

```jsx
{isPaused ? <p>See you later!</p> : <Counter />}
```

한쪽 분기는 `<p>`, 다른 쪽은 `<Counter />`입니다. 같은 위치인데 타입이 다르니 토글 순간 Counter는 unmount되고 score는 0으로 돌아갑니다. 다시 켜도 새 컴포넌트, 새 state입니다.

## 흔한 실수

- **부모 태그를 갈아끼우면 같은 줄이라 보존될 거라 착각.** `<section><Counter/></section>`을 `<div><Counter/></div>`로 바꾸면 트리 구조 자체가 달라져 그 하위 전체가 새로 만들어집니다. score는 리셋됩니다 [slide 6].
- **"props가 바뀌었으니 state도 리셋되겠지"** 라는 선입견. props는 state 보존 여부와 직접 관련이 없습니다. 위치와 타입만 보세요.

## 복습

state는 컴포넌트 인스턴스가 아니라 트리 위치에 묶입니다. 같은 위치 + 같은 타입이면 보존, 타입이 다르면 리셋. 다음 class([S4.C2])에서는 일부러 리셋하고 싶을 때 쓰는 두 전략을 봅니다.
