# 코스 맵 — 7개 챕터가 어떤 통증을 푸는가

> LOs: LO-S0.1, LO-S0.2

## 개요
앞 class [S0.C1]에서 본 4가지 통증(중복·동기화·drilling·리셋)을 머릿속에 두고, 이제 "어디서 어떻게 풀리는지"를 한 장의 지도로 확인합니다 [slide 1]. 오늘의 약속은 두 가지예요. 첫째, S1~S7 7개 챕터를 통증과 1:1로 매핑해서 **북극성**처럼 다시 펴볼 지도를 손에 쥐는 것. 둘째, 학습자 본인 코드 한 줄을 어느 챕터에 걸어볼지 가설을 세우는 짧은 self-diagnosis로 오리엔테이션을 닫는 것입니다.

## 핵심 개념
7개 챕터는 두 묶음으로 기억하면 됩니다 [slide 2].

**구조 잡기 (S1·S2·S3) — state를 어디에 어떤 모양으로 둘지 결정**
- **S1 선언형 사고:** 통증 #1·#2의 뿌리 처방. visual states 열거 → 트리거 식별 → `useState` 모델링 → 비핵심 제거 5단계.
- **S2 state 구조 설계:** 통증 #1(중복)·#2(동기화) 직접 차단. 5원칙(묶기 / 모순 회피 / redundant 제거 / duplication 회피 / 평탄화).
- **S3 lifting state up:** 통증 #3(drilling)의 1차 처방. 형제 협조가 필요할 때 공통 부모로 끌어올리고 single source of truth 확립.

**동작 다듬기 (S4·S5·S6·S7) — 구조 위에서 리셋·로직·전달을 정교화** [slide 3]
- **S4 state 보존과 리셋:** 통증 #4 정면 해결. 트리 위치 규칙 + `key` prop으로 리셋 의도를 표현.
- **S5 reducer:** 흩어진 `setState`를 `(state, action) => nextState` 순수 함수로 통합.
- **S6 context:** 통증 #3의 2차 처방. `createContext` / `Provider` / `useContext` 3단계.
- **S7 reducer + context:** 대규모 분산 상태 확장. state/dispatch context 분리 + 커스텀 훅 응집.

핵심은 "통증 ↔ 챕터"가 **우연이 아니라 의도된 매핑**이라는 점입니다. 막연히 "언젠가 배우면 도움될 것"이 아니라, 지금 손에 쥔 통증을 **어느 정거장에서 내릴지** 정해두면 학습 동력이 달라져요.

## 예시
구체 매핑 두 개를 봅시다 [slide 4].

- "체크박스 7개를 boolean으로 들고 있다가 모순 상태가 만들어진 폼" → **S1·S2**. status enum 패턴과 5원칙으로 풀립니다 (앞 class의 boolean paradox 예시가 정확히 여기 걸립니다).
- "같은 폼인데 탭만 바꾸면 입력이 그대로 남아 새 글에 옛 값이 보이는 화면" → **S4**. `key` prop 한 줄로 리셋 의도를 표현합니다.

```tsx
// S4의 예고편 — 같은 폼이지만 글 ID가 바뀌면 리셋
<PostForm key={postId} initialValue={post.draft} />
```

이 한 줄이 왜 통증 #4를 푸는지는 S4에서 다루지만, 지금은 **"통증마다 풀리는 챕터가 정해져 있다"**는 감각만 잡으면 충분합니다.

## 흔한 실수
- 코스 맵을 한 번 보고 덮어버리는 것. 이 지도는 **북극성**입니다 — 챕터 진입할 때마다 "내 가설은 여기서 검증되는가?"를 물어야 살아있는 지도가 됩니다 [slide 5].
- 자기 코드 가설 없이 강의를 듣는 것. 4가지 통증 중 **하나라도** 본인 프로젝트에서 라벨링해 두지 않으면 이 강의는 추상적인 React 문서 요약처럼 들립니다.

## 복습
정리 [slide 6]: ① S1·S2·S3은 **구조 잡기**, S4~S7은 **동작 다듬기** 두 묶음. ② 4가지 통증은 7개 챕터 어딘가에서 반드시 풀린다 — 우연으로 두지 않습니다. ③ 다음 섹션 [S1.C1]부터는 **가설을 들고 입장**하세요. 본인 코드의 어느 줄이 어느 챕터에 걸리는지 추적하며 듣는 게 이 강의를 가장 잘 쓰는 방법입니다.
