[slide 1]
검색창에 a, ab, abc를 빠르게 입력했더니, 이상한 일이 벌어집니다.
[pause:500]
abc의 결과가 떠야 할 자리에, 한 글자 a의 결과가 표시되는 거예요.
[pause:500]
응답이 늦게 도착한 게 마지막에 도착해서, 화면을 덮어 버린 거죠. 레이스 컨디션입니다.
[pause:600]
또 다른 케이스. 온라인 상태 표시기가 같은 페이지 두 곳에 있는데, 두 표시기가 살짝 어긋나서 깜빡거립니다.
[pause:600]
오늘은 마지막 두 안티패턴, 11번 외부 스토어 구독과 12번 페치 레이스를 다루고, 종합 결정 트리로 섹션을 닫습니다.

[slide 2]
안티패턴 11번이에요.
[pause:500]
네비게이터 닷 온라인 같은 리액트 외부 스토어를, 유즈이펙트와 애드이벤트리스너로 수동 구독하는 패턴입니다.
[pause:600]
문제가 두 가지예요.
[pause:500]
첫째, 두 컴포넌트가 각자 구독하면 티어링이 발생할 수 있어요. 두 곳의 값이 잠깐 어긋나는 거죠.
[pause:500]
둘째, 서버 사이드 렌더링 초기값 처리가 까다롭습니다.
[pause:600]
정답은 유즈싱크익스터널스토어입니다.
[pause:500]
인자를 세 개 받아요. 섭스크라이브, 겟스냅샷, 그리고 겟서버스냅샷.
[pause:600]
섭스크라이브 함수는 컴포넌트 외부에 정의해서 한 번만 만듭니다.
[pause:500]
스냅샷 게터는 매번 호출돼서 최신값을 반영해요. 리액트가 일관성을 보장합니다.

[slide 3]
코드로 봅시다. 유즈온라인스테이터스 훅이에요.
[pause:600]
비포는 이렇게 생겼습니다.
[pause:400]
유즈스테이트로 이즈온라인을 네비게이터 닷 온라인 초기값으로 두고, 유즈이펙트 안에서 업데이트 함수를 정의합니다.
[pause:500]
윈도우에 온라인과 오프라인 이벤트를 등록하고, 클린업에서 다시 제거하죠.
[pause:600]
애프터는 훨씬 깔끔해요.
[pause:500]
섭스크라이브 함수를 컴포넌트 밖에 정의해서, 콜백을 받고 두 이벤트에 등록하고, 클린업 함수를 반환합니다.
[pause:500]
유즈온라인스테이터스 훅 안에서는 유즈싱크익스터널스토어를 호출하고, 인자로 섭스크라이브, 그리고 네비게이터 닷 온라인 게터, 마지막으로 서버 기본값 트루를 넘깁니다.
[pause:600]
이제 다른 컴포넌트에서 같은 훅을 호출해도 티어링이 없어요. 서버 사이드에서도 트루를 기본값으로 받습니다.

[slide 4]
안티패턴 12번. 페치 인 이펙트의 레이스 컨디션이에요.
[pause:500]
유즈이펙트 안에서 페치를 호출하고, 의존성에 query와 page를 두는 흔한 패턴이죠.
[pause:500]
query나 page가 빠르게 바뀌면, 응답 순서가 어긋나서 스테일한 결과가 화면에 박힐 수 있습니다.
[pause:600]
처방을 단계별로 봅시다.
[pause:500]
1차 처방, 클린업에서 이그노어 플래그를 세웁니다. 이전 응답을 무시하는 거죠.
[pause:600]
2차 처방, 유즈데이터 같은 커스텀 훅으로 패턴을 캡슐화합니다.
[pause:500]
컴포넌트는 그냥 const data 이콜 유즈데이터, 인자로 유알엘 한 줄이면 끝나요.
[pause:600]
3차 처방, 프로덕션에서는 리액트 쿼리, 에스더블유알, 또는 알에스시 같은 데이터 레이어를 씁니다.
[pause:500]
캐싱, 취소, 중복 요청 처리가 자동으로 됩니다.

[slide 5]
코드 단계별로 따라가 봅시다.
[pause:600]
비포는 유즈이펙트 안에서 페치리절츠를 호출하고, 결과를 셋리절츠로 그냥 넣어요. 의존성에 query와 page.
[pause:500]
레이스 컨디션 그대로입니다.
[pause:600]
1차 애프터는 이그노어 플래그를 추가해요.
[pause:400]
이펙트 안에서 렛 이그노어를 false로 두고, 페치리절츠 닷 덴 콜백에서 이그노어가 거짓일 때만 셋리절츠를 호출합니다.
[pause:400]
클린업에서는 이그노어를 true로 만들어 이전 요청을 무시하게 하죠.
[pause:600]
2차 애프터는 그 패턴을 유즈데이터 훅으로 캡슐화하는 겁니다.
[pause:500]
호출하는 쪽은 const 리절츠 이콜 유즈데이터, 안에 슬래시 에이피아이, 쿼리, 페이지가 들어간 유알엘 한 줄이에요.
[pause:600]
단계는 이렇게 정리됩니다. 이그노어 추가, 클린업 추가, 그리고 유즈데이터로 추출.

[slide 6]
이제 결정 트리를 12 패턴 위에 한 장으로 합쳐서 봅시다.
[pause:600]
큐원, 렌더 중에 계산 가능? 변수 한 줄이면 끝. 1번 패턴.
[pause:500]
큐투, 비싼가? 유즈메모. 2번 패턴.
[pause:500]
큐쓰리, 인터랙션 결과? 핸들러. 5번부터 10번 패턴.
[pause:500]
큐포, 프롭이 바뀔 때 리셋? 키 프롭으로 가면 3번, 디라이브드나 스테이트 듀링 렌더로 가면 4번.
[pause:500]
큐파이브, 외부 스토어? 유즈싱크익스터널스토어, 11번 패턴.
[pause:500]
페치라면 이펙트와 이그노어 또는 유즈데이터, 12번 패턴이죠.
[pause:600]
12 패턴이 다섯 질문, 다섯 리프로 깔끔하게 흡수됩니다.

[slide 7]
새 시나리오 세 개를 결정 트리로 정당화해 봅시다.
[pause:600]
첫째, 검색 입력에 따라 결과 갱신.
[pause:500]
큐파이브에서 외부 에이피아이로 분기됩니다. 페치와 이그노어, 또는 유즈데이터로 가는 거죠.
[pause:600]
둘째, 장바구니 합계.
[pause:500]
큐원에서 끝나요. 렌더 중에 계산하면 됩니다. 비싸지 않으면 유즈메모도 필요 없어요.
[pause:600]
셋째, 라우트 변경 시 분석 로그.

[pause:600]
각 선택에 대해 "왜 이 도구인가"를 한 문장으로 답하는 연습을 해 보세요.

페치 인 이펙트는 항상 이그노어 클린업, 또는 유즈데이터로 캡슐화하세요.
