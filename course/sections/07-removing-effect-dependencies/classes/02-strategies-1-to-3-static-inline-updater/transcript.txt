[slide 3]
전략 1, 정적값 외부화입니다.
[pause:400]
진짜 상수를 컴포넌트 밖으로 옮기세요.
예를 들어 serverUrl이 https로 시작하는 고정 문자열이라거나, roomId가 'music'으로 박혀 있는 경우예요.
[pause:500]
컴포넌트 밖, 즉 모듈 스코프에 있는 값은 reactive가 아닙니다.
린터도 뎁스에 요구하지 않아요.
[pause:400]
적용 신호는 이 질문 한 줄이에요.
"이 값은 절대 안 바뀌는데, 왜 뎁스에 있지?"
[pause:500]
한 가지 주의.
prop이나 state는 절대 컴포넌트 밖으로 옮길 수 없어요.
그건 진짜 상수가 아니에요.
컴포넌트마다 다를 수 있는 값이거든요.

[slide 4]
전략 2.
매 렌더 새로 생기는 객체나 함수는, Effect 안에서 만드세요.
[pause:400]
예를 들어 ChatRoom 컴포넌트가 roomId를 prop으로 받는다고 해볼게요.
[pause:300]
컴포넌트 본문에 const options를 serverUrl과 roomId로 만들어 두면, 매 렌더마다 새 참조가 생깁니다.
뎁스에 options를 넣으면 매번 다르다고 판단해서 재연결이 폭주해요.
[pause:500]
해결은 간단합니다.
useEffect 안으로 options 정의를 옮기세요.
그리고 뎁스에는 원시값 roomId만 넣어요.
[pause:400]
원시값은 Object.is 비교에서 안정적이에요.
같은 문자열이면 같다고 판단하거든요.
[pause:400]
적용 신호는 이거예요.
객체나 함수 뎁스 때문에 무한 재실행이 일어날 때.

[slide 5]
전략 3, 업데이터 함수예요.
[pause:400]
state를 "읽기만" 한다면, 업데이터 함수로 의존성 자체를 끊어버릴 수 있어요.
[pause:400]
setX에 prev 화살표 next 형태를 넣으면, React가 최신 state를 인자로 넣어줘요.
Effect가 직접 state를 읽을 필요가 없어집니다.
[pause:500]
예를 들어 messages 의존을 끊는 경우.
c.on('message') 콜백 안에서 setMessages를 호출하는데, 이때 prev 화살표로 새 배열을 만들면 돼요.
[pause:400]
원래 뎁스가 roomId, messages였다면, 이제 roomId만 남습니다.
[pause:500]
적용 신호는 누적, 토글, 카운트업처럼 "쓰기 위해 읽는" 패턴이에요.
[pause:400]
이 한 줄이 다 해결합니다.

[slide 6]
이제 처음에 보여드린 깜빡이는 타이머를 직접 고쳐볼게요.
[pause:400]
Before 코드.
useEffect 안에서 setInterval에 setCount에 count + 1을 넣고, 뎁스는 count예요.
[pause:500]
문제를 추적해 봅시다.
count가 변경되면, Effect가 재실행돼요.
cleanup이 interval을 해제하고요.
새 interval을 등록합니다.
이걸 매 초마다 폐기하고 재생성하는 거예요.
[pause:500]
After.
딱 한 글자만 바꿉니다.
setCount에 count + 1 대신, c 화살표 c + 1을 넣어요.
업데이터 함수죠.
그리고 뎁스를 빈 배열로.
[pause:500]
결과는요?
interval은 mount 시 한 번만 등록됩니다.
count는 항상 최신값이고요, 매 tick마다 c가 최신값으로 들어와요.
[pause:400]
한 줄 변경의 위력 보이시죠?
클로저 캡처 문제와 재생성 문제를 동시에 해결했어요.
